# Code Solver 1.0 规格

- 状态：当前版本
- 日期：2026-08-13
- 基线：已有轻量解题与代码审查能力
- 适用范围：算法题解、代码审查、每日一题、专项训练与复盘

## 1. 目标

帮助用户形成“识别题型 → 选择方法 → 写出代码 → 记录复盘”的刷题闭环，同时保持解题流程轻量、产物可运行、训练进度可持续。

## 2. 命令与结果

| 能力 | 命令 | 默认值 | 结果 |
|---|---|---|---|
| 快速解题 | `solve fast <题目> [语言]` | Java 17、中文 | 简洁题解与可运行代码 |
| 深度解题 | `solve detail <题目> [语言]` | Java 17、中文 | 详细题解、代码、独立测试代码 |
| 代码审查 | `review [--rules <路径>] <代码或报错>` | 内置规则 | 审查结论与最小修改建议 |
| 每日一题 | `train daily [days] [goal]` | 30 天、每天一题 | 训练计划、今日题、进度、总结 |
| 专项训练 | `train drill <topic> [count] [goal]` | 7 题 | 递进计划、当前题、专题总结 |
| 提交记录 | `train submit <代码或描述>` | 当前计划 | 静态评估与进度记录 |
| 训练总结 | `train summary` | 当前计划 | 当前计划总结 |

## 3. 核心流程

### 3.1 Solve

1. 确定题目、语言与归档路径。
2. 先生成并归档题解。
3. 再生成单文件、标准库、带运行入口的代码。
4. detail 在同一代码阶段额外生成独立测试代码。
5. 完成后停止，由用户自行运行和验证。

### 3.2 Review

按单一最高优先级规则执行：本次请求规则 → `--rules` 指定规则 → 项目规则 → 内置规则。输出问题必须包含位置、证据、影响、优先级和最小修改；没有证据不输出问题。

### 3.3 Training

1. 创建计划时优先复用已有题解与代码，并引用同题型笔记或公开资源。
2. 当前题缺少归档时，复用 solve 流程补齐后关联计划。
3. 用户可提交代码或文字描述；代码仅做静态评估，文字按用户自述记录。
4. 记录 `completed`、`partial`、`blocked`、`skipped` 四种状态。
5. 计划结束时生成总结；专项总结额外沉淀识别信号、通用步骤、边界清单和代表题阶梯。

## 4. 归档

```text
code-solver-workspace/
├── <平台>/<中文题型>/<题号>-<题名>-<语言>/
│   ├── 题解.md（审查场景为 审查.md）
│   ├── Main.java 或 solution.*
│   └── Test.java 或 test.*（仅 detail）
└── training/daily|drill/<计划名>/
    ├── 计划.md
    ├── state.json
    ├── 进度.md
    ├── history.jsonl
    ├── 总结.md
    └── submissions/
```

训练计划引用既有笔记，不复制题面、官方题解或付费内容。

## 5. 边界

- 不创建临时文件，不回读刚写入的题解或代码。
- 不编译、不运行、不自动修复生成代码。
- detail 测试优先使用官方样例，仅补必要边界。
- daily 当天完成后不提前派发下一题；drill 可继续下一题。
- 旧归档不迁移、不扫描。

## 6. 验收

- [ ] 命令、输出、归档与边界完整可描述。
- [ ] solve、review 与 training 的职责互不混淆。
- [ ] 训练可复用已有笔记，并支持提交、进度和总结闭环。
- [ ] 1.0 的更新内容可在 CHANGELOG 中独立追溯。
