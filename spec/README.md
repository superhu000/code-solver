# Code Solver Spec

## 当前版本

当前仅保留 **1.0**，入口为 [1.0/SPEC.md](1.0/SPEC.md)。

```text
spec/
├── README.md                 # 本目录与版本管理规则
└── 1.0/
    ├── SPEC.md               # 1.0 当前完整规格
    └── CHANGELOG.md          # 1.0 更新内容与变更影响
```

## 文件职责

| 文件 | 回答的问题 | 修改时机 |
|---|---|---|
| `1.0/SPEC.md` | 当前版本“做什么、怎么做、边界是什么” | 功能契约发生变化 |
| `1.0/CHANGELOG.md` | 当前版本“相较上一基线更新了什么、影响什么” | 每次功能、行为或兼容性变更 |
| `README.md` | Spec 如何组织和维护 | 结构或版本规则变化 |

## 版本管理规则

1. 一个发布版本对应一个独立目录：`spec/<major.minor>/`。
2. 当前只有 `spec/1.0/`；旧的 0.x Spec 已移除，不再并存。
3. 每次准备发布新版本时，从当前目录复制创建新目录，例如 `spec/1.1/`，不要覆盖 `1.0/`。
4. 新版本目录必须同时含 `SPEC.md` 与 `CHANGELOG.md`：前者写完整现状，后者按“新增 / 变更 / 移除 / 兼容性”列出差异。
5. 运行时文档与实现的同步属于发布验收，不在本次 Spec 重构范围内。

## 写作约定

- `SPEC.md` 使用“目标、命令、流程、数据、边界、验收”结构。
- `CHANGELOG.md` 必须标明版本、日期、基线、影响范围，并只记录可核对的变更。
- 不把实现细节、临时讨论或重复题解模板写入版本说明。
