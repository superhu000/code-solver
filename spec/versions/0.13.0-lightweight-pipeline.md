# Code Solver 0.13.0 增量 Spec：轻量题解优先流水线

- 状态：已实现
- 日期：2026-08-13
- 基线：0.12.0
- 目标版本：0.13.0
- 适用范围：`solve fast`、`solve detail`、`review` 与新归档

## 1. 问题

0.12.0 的说明引用了仓库中不存在的解析、流水线、模板和安装文件；主 Skill 同时承载大量语言模板、运行命令和流程说明。实际执行容易发生额外读取、重复推理、临时产物和环境验证，导致首个用户可见结果变慢。

## 2. 决策

1. 题解是 solve 的第一产物，模型按当前模式模板一次生成后直接写入最终目录。
2. fast 固定两轮：题解一轮、可运行代码一轮。
3. detail 固定两轮：详细题解一轮；解题代码与测试代码在同一轮生成。
4. detail 生成测试代码文件，不生成测试说明或测试报告文档。
5. solve 第一轮读取对应模式模板文件（`references/fast-template.md` 或 `references/detail-template.md`），不读取 Spec；生成代码时复用当前上下文，不回读题解。
6. review 读取 `references/review-template.md` 输出模板和一个最高优先级规范源，用户上传或指定内容优先。
7. 归档只调用一次短脚本，产物直接写入扁平最终目录。
8. Skill 不编译、不运行、不在终端验证或自动修复生成代码，由用户测试。

## 3. 模式契约

| 模式 | 生成轮次 | 顺序 | 文件写入 | 额外读取 |
|---|---:|---|---:|---:|
| fast | 2 | 简洁题解 → 解题代码 | 2 | 1 个模板文件 |
| detail | 2 | 详细题解 → 解题代码 + 测试代码 | 3 | 1 个模板文件 |
| review | 1 | 规范审查 | 1 | 1 个规范源 |

题面缺少关键契约时只允许一次澄清。题面完整时不得调用网络或解析脚本重新获取相同信息。

## 4. Detail 测试代码

- 必须具有用户可运行入口且只使用标准库。
- 必须调用解题代码公开接口，不复制算法实现。
- 优先使用题面提供的官方样例；不得将自造用例标记为官方。
- 官方样例不足时只补充 1～3 个关键边界。
- 输出明确的通过/失败信息。
- Skill 只生成文件，不执行测试。

### 审查流程

1. **解析归档**：确定平台、题号、题名、语言和题型，调用 `archive.py resolve --mode review`。
2. **读取模板与规范**：并行读取 `references/review-template.md`（输出模板）和按优先级选中的规范源。
3. **一次生成代码审查**：按模板占位符结构，结合规范规则，一次生成完整 Markdown 写入 `代码审查.md`。
4. **保存**：不运行被审代码，不编译，不创建额外文件。

### 审查输出结构

| 章节 | 内容 |
|---|---|
| 用户代码 | 保留用户原始代码，用行内注释标注问题位置 |
| 代码审查 | 一段话总结：可编译性、思路正确性、复杂度、问题数量及整体质量 |
| 思路分析 | 分析算法思路是否正确，是否满足约束，是否忽略边界；正确则分析是否最优 |
| 语法检查 | 逐行检查语法，结合代码规范指出问题，标注优先级：阻断 / 重要 / 建议 |
| 优化代码 diff | unified diff 格式输出修改建议，`+` 行附带注释说明改动意图 |
| 问题分析 | 对 diff 中每个错误点逐一分析：优先级、位置、证据、影响 |
| 盲点补全 | 语法与算法盲点分析、2-3 道刷题建议（标注平台题号）、学习资源推荐（开源项目 / 书籍 / 文档） |

## 6. 新归档契约

```text
code-solver-workspace/<平台>/<中文题型>/<题号>-<题名>-<语言>/
├── 题解.md（review 为 审查.md）
├── Main.java（或 solution.*）
└── Test.java（或 test.*，仅 detail）
```

兼容策略：不迁移、不扫描旧归档；新任务直接使用新结构。路径组件清理 Windows 非法字符，保留中文题名和题型。

## 7. 文件边界

| 文件 | 职责 | 运行时读取 |
|---|---|---|
| `SKILL.md` | 路由、两轮流程、模板引用和性能预算 | 始终 |
| `command/code-solver.md` | 命令入口与关键约束 | 命令触发时 |
| `scripts/archive.py` | 创建一次最终目录、返回路径、可选列举归档 | solve/review 各一次 |
| `references/fast-template.md` | fast 题解模板 | solve fast 第一轮 |
| `references/detail-template.md` | detail 题解模板 | solve detail 第一轮 |
| `references/review-template.md` | review 审查输出模板 | review 第一轮 |
| `references/review-rules.md` | 默认审查规则 | 仅 review 且无覆盖 |
| 本增量 Spec | 版本决策与验收依据 | 不读取 |

限制：`SKILL.md` 控制在 250 行以内，其他单个运行时文件控制在 150 行以内；不增加解析器或渲染器。题解模板独立为 `references/` 下的可编辑文件，用户可按需修改风格。

## 8. 验收标准

- [x] fast 第一写入文件为 `题解.md`，随后只写一个解题代码文件。
- [x] detail 第一写入文件为 `题解.md`，第二轮生成代码与测试代码。
- [x] detail 不创建额外测试 Markdown。
- [x] solve 路径不读取 Spec，不回读产物；模板从 `references/` 读取一次。
- [x] review 读取 `review-template.md` 输出模板，按占位符结构一次生成完整审查。
- [x] review 审查输出包含：用户代码、代码审查总结、思路分析、语法检查、优化代码 diff、问题分析、盲点补全（含刷题建议与学习资源推荐）。
- [x] 所有生成代码与测试的契约明确为单文件、标准库、可运行入口。
- [x] 明确禁止 Skill 编译、运行和终端验证生成代码。
- [x] README、命令入口和 Skill 使用同一模式名称与归档结构。

## 9. 验证边界

本增量只做静态结构、Frontmatter、路径引用和行数检查；不编译或执行算法代码、测试代码与归档脚本。实际题目运行结果由用户验证。
